# Exam Seating Allocation System — AI Instruction File

## 1. System Requirements

An exam seating allocation system that assigns students to seats across multiple exams in a semester, ensuring no two students with conflicts (same class, same subject, or previously adjacent in a prior exam) sit next to each other. It combines **p-dispersion** for optimal seat selection with **graph coloring** for conflict-free student-to-seat assignment. The application follows a 4-phase pipeline: (1) Setup — select total exams (1–10); (2) Upload — upload one CSV per exam and configure the room layout; (3) Processing — process seat maps sequentially, carrying conflict history forward between exams; (4) Review — display results with conflict badges, with options to rerun conflicted exams or export results. A configurable memory window (default: 3) controls how many past exams are retained for conflict avoidance. Per exam, the solver runs up to 50 iterations with randomized seeds. Exams with remaining conflicts can be rerun with up to 20 independent random trials. Each CSV contains student data (`id,name`); the parser auto-detects headers and handles quoted fields.

## 2. Algorithm Concepts

**P-Dispersion:** Given available seats, select N seats that maximize the minimum pairwise distance, solved via a WebAssembly module (`solve_exact`, `solve_greedy`, `solve_random`). **Graph Coloring:** Students are assigned to the selected seats using constraint satisfaction — nodes are students, edges are conflict relationships (same group or 8-way adjacent in prior exams), and colors are seats. **Solver strategies (in order):** (1) Backtracking with forward checking — orders seats by degree, prunes domains, backtracks on wipeout; (2) DSatur — greedy fallback using degree of saturation; picks minimum-conflict student when no valid option exists; (3) Randomized variant — seeded Mulberry32 PRNG with Fisher-Yates shuffle to explore different orderings. After each exam, assignment history accumulates into a forbidden pairs set to maximize separation across the semester.

## 3. Available Tools & Project Structure

**Tech stack:** React 19.x, TypeScript 5.x (strict), Vite 7.x, WebAssembly (via `vite-plugin-wasm`), html2canvas, jsPDF, ESLint 9.x. **Structure:** `src/App.tsx` (state manager, pipeline orchestration); `src/components/` (Board, ControlPanel, CsvUploadPanel, ExamReview, ExamSetup, SeatMapModal, NumberField); `src/utils/` (graphColoring.ts — solvers and forbidden pairs; csvUtils.ts — parser; exportUtils.ts — CSV/PNG/PDF export; cellKey.ts — key helper); `src/hooks/` (useDragSelect.ts); `src/constants/` (grid and pipeline configuration); `demo/` (sample CSVs). **Key types:** `Student {id, name}`, `Assignment {student, point, hasConflict?}`, `ExamResult {examId, assignments, conflictCount, seatMap, status}`, `PipelinePhase`, `Algorithm`.

## 4. Coding Style

**TypeScript:** Strict mode, interfaces for data shapes, discriminated unions for enum-like types, explicit types at function boundaries. **React:** Functional components with hooks; all state in `App.tsx` via `useState`; `useCallback` for performance-critical handlers; props as a single destructured object. **Naming:** `camelCase` for variables/functions, `PascalCase` for components/types, `on*` prefix for event handlers, `UPPER_SNAKE_CASE` for constants. **Organization:** Separation of concerns (`components/`, `utils/`, `hooks/`, `constants/`); arrow function declarations; `/* ── Title ── */` section headers. **CSS:** Custom properties, CSS Grid, dark theme, responsive breakpoints.
